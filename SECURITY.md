# Security reporting

Do not disclose vulnerability details in public issues, pull requests, or logs. Do not include real recordings, transcripts, clipboard contents, tokens, or encryption keys.

Use [GitHub private vulnerability reporting](https://github.com/0Litost0/SeaSnail/security/advisories/new) when it is enabled. If that page is unavailable, open an issue containing only “Please provide a private security contact” without technical details, and wait for a private channel. A working private reporting channel must be configured before public release.

Include affected versions, a minimal reproduction with synthetic data, impact, and any proposed fix. Let the maintainers coordinate a fix and disclosure. No response-time guarantee or bug-bounty program is currently offered.

SeaSnail is in early development. Only the latest maintained revision is a candidate for fixes; unsigned development builds are not signed production releases. See [release requirements](doc/releasing.md).
